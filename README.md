# בוט RAG לנהלי הארגון

בוט שעונה על שאלות עובדים מתוך מסמכי הארגון. נבנה עם LlamaIndex, Chroma, Gemini ו-Streamlit.

## המבנה: כל שלב וקובץ

| שלב | קובץ |
|---|---|
| הגדרות (כל ההחלטות) | `config.py` |
| יצירת שני המודלים | `models.py` |
| **הכנה:** טעינה, חלוקה לסעיפים, וקטורים, שמירה ב-Chroma | `ingest.py` |
| חיפוש מילות מפתח (BM25) | `keyword_search.py` |
| **זמן אמת:** הרחבה, חיפוש היברידי, פרומפט, תשובה | `rag.py` |
| ממשק צ'אט | `app.py` |
| תיקון תעודות HTTPS מאחורי סינון (ראו בעיה 3) | `windows_certificates.py` |
| בדיקת המפתח והמודלים הזמינים | `check_models.py` |

## הרצה

```bash
python -m venv venv
venv\Scripts\activate             # Mac/Linux: source venv/bin/activate
pip install -r requirements.txt
copy .env.example .env            # Mac/Linux: cp .env.example .env
# ממלאים את GOOGLE_API_KEY בקובץ .env

python check_models.py            # בודק את המפתח ומציג מודלים זמינים
python ingest.py                  # בונה את מסד הוקטורים
streamlit run app.py              # מפעיל את הבוט
```

את המסמכים שמים בתיקייה `data/`. אחרי כל שינוי במסמכים, או החלפה של מודל ה-Embedding, מריצים שוב `python ingest.py`.

## מגבלות

- בשכבה החינמית של Gemini יש מגבלות קצב, ותוכן שנשלח עשוי לשמש את Google. לכן משתמשים בה רק במסמכים לא סודיים.
- חיפוש מילות המפתח לא מזהה צורות שונות של מילה ("בית" מול "מהבית"). את זה החיפוש הסמנטי משלים.
- כשסעיף ארוך נחתך, רק הקטע הראשון שלו כולל את כותרת הסעיף.

## בעיות שנתקלתי בהן ופתרונות

### בעיה 1: גרסת Python ישנה מדי

**מה קרה:** התקנת הספריות (`pip install -r requirements.txt`) נכשלה. בבדיקה עם `python --version` התברר שמותקן **Python 3.8.6rc1**.

**הסיבה:** ספריות LlamaIndex דורשות **Python 3.10 ומעלה**. בנוסף, הגרסה שהייתה מותקנת היא גרסת ניסיון (rc) ולא גרסה סופית.

**הפתרון:**
1. התקנתי את Python 3.12 (הגרסה הישנה נשארה, ושתיהן יכולות לחיות זו לצד זו).
2. מחקתי את הסביבה הווירטואלית הישנה, שנבנתה על 3.8, ויצרתי חדשה על 3.12:
```powershell
Remove-Item -Recurse -Force venv
py -3.12 -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

**הלקח:** לפני שמתחילים פרויקט בודקים את הדרישות של הספריות, כמו גרסת Python. סביבה וירטואלית קשורה לגרסת ה-Python שבה נוצרה, ולכן אחרי שדרוג בונים אותה מחדש.

---

### בעיה 2: `ModuleNotFoundError` אף שהספריות הותקנו

**מה קרה:** בהרצת `python check_models.py` הופיעה השגיאה `No module named 'google'`, ובפעם אחרת `No module named 'dotenv'`, אף שהספריות הותקנו בהצלחה.

**הסיבה:** הקובץ הורץ **מחוץ לסביבה הווירטואלית**, בחלון PowerShell חדש שבו לא הופיע `(venv)` בתחילת השורה. במצב כזה רץ Python 3.8 הישן, והספריות של הפרויקט לא מותקנות בו. כל סביבה וירטואלית מחזיקה ספריות משלה.

**הפתרון:** הפעלת הסביבה בכל חלון חדש, ובדיקה איזה Python רץ ואיפה הספרייה מותקנת:
```powershell
venv\Scripts\activate
python --version          # צריך להציג 3.12
pip show google-genai     # השורה Location צריכה להצביע לתוך venv
```

**הלקח:** כשספרייה "לא נמצאת", בודקים קודם **איזה Python רץ** ו**איפה הספרייה מותקנת**, ורק אחר כך מתקינים מחדש.

---

### בעיה 3: שגיאת תעודה (SSL) בגלל סינון האינטרנט

**מה קרה:** חיבורים מאובטחים (HTTPS) נכשלו בשגיאה:
```
SSL: CERTIFICATE_VERIFY_FAILED  certificate verify failed: unable to get local issuer certificate
```
השגיאה הופיעה בשלושה מקומות: ב-**pip** בהורדת הספריות, ב-**winget** בהתקנת Python מה-Microsoft Store, וב-**חיבור ל-Gemini** (`check_models.py`).

**הסיבה:** הבעיה לא הייתה בקוד אלא בחיבור לאינטרנט. החיבור עובר דרך הסינון **NetFree**, שמחליף את התעודות של האתרים בתעודות שלו. הדפדפן ו-Windows סומכים על התעודות האלה, כי NetFree התקין את תעודות השורש שלו ב-Windows. אבל ספריות Python בודקות לפי רשימת תעודות משלהן (`certifi`), ושם התעודות של NetFree לא מופיעות.

**מה ניסיתי ולמה זה לא עבד:**
| ניסיון | תוצאה |
|---|---|
| התקנה של Python דרך מקור winget במקום ה-Microsoft Store (`--source winget`) | עבד להתקנת Python |
| Python 3.12 עם pip חדש | עבד להתקנת הספריות, כי pip החדש משתמש במאגר של Windows |
| קובץ התעודות ש-NetFree מספק, ותעודה שייצאתי מהדפדפן | נכשל: חסרה תעודת ביניים בשרשרת ("NetFree Node Intermediate CA") |
| קובץ תעודות מכל התעודות של Windows ושל NetFree | נכשל מאותה סיבה |
| העברת בדיקת Windows לספרייה של Gemini דרך `http_options` | עבד בבדיקה, אבל LlamaIndex ממיר את ההגדרות לטקסט (JSON) ונכשל בשגיאה `PydanticSerializationError` |

כדי להפסיק לנחש, כתבתי סקריפט אבחון שבדק כמה דרכים במקביל. הוא הראה ש**כש-Windows עצמו בודק את התעודה, כמו בדפדפן, החיבור מצליח**.

**הפתרון:** הקובץ `windows_certificates.py`, ש-`config.py` טוען ראשון, לפני כל חיבור. הוא משתמש בספרייה `truststore`, כך שכל חיבור HTTPS בתוכנית נבדק על ידי Windows, ומתעלם מרשימות התעודות הפרטיות של הספריות. התיקון פועל על כל התוכנית בבת אחת: LlamaIndex, Gemini ו-Chroma.

**הלקח:**
- אותה הודעת שגיאה יכולה לנבוע מהרשת ולא מהקוד. הרמז היה שהשגיאה הופיעה בכמה כלים שונים, בזמן שהדפדפן עבד תקין.
- כשפתרון לא עובד, עדיף לכתוב בדיקה שמראה בדיוק איפה הבעיה, במקום לנחש.
- פתרון שעובד בבדיקה קטנה צריך לבדוק גם בתוך הספריות האמיתיות.
